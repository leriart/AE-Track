# 5.14.3

Dialogo de error de la IA mas util: cuando una llamada falla (timeout,
401, 404, 429, 400, JSON invalido), el operador ve ahora **el endpoint
que se intento**, **un tip especifico del proveedor** y **botones para
cambiar a otro proveedor con 1 click**.

## Problema que se resolvio

Antes, en 5.14.2, el dialogo de error mostraba el mensaje crudo y una
pista generica ("Verifica tu conexion y reintenta"). Eso dejaba al
operador a ciegas:

- No sabia **que endpoint** estaba intentando (importante para
  distinguir Kimi-for-Coding vs Moonshot, que son productos
  distintos con keys distintas).
- No sabia **que era un problema del proveedor Kimi** y que la
  solucion era cambiar a DeepSeek.
- Para cambiar de proveedor tenia que ir a Ajustes > IA > abrir el
  desplegable, seleccionar otro, guardar, salir, volver a pulsar
  "Detectar patrones". 5-6 clicks.

## Cambios

### Nuevo helper `mostrarDialogoErrorIA(r, contexto)`

Centraliza el dialogo de error (antes se repetia inline en
`aiPatronesUI` y `aiAnalizarLoteUI`). El dialogo ahora muestra:

1. **Proveedor** (nombre legible, no la clave interna).
2. **Endpoint** en monospace dentro de un recuadro, para que el
   operador verifique que la URL es la correcta.
3. **Detalle** del error completo.
4. **Sugerencia** contextual segun el patron del error
   (400/401/429/timeout/JSON parseable/etc).
5. **Tip del proveedor**: parrafo especifico para Kimi, Moonshot,
   DeepSeek, NVIDIA o MiniMax. P.ej. para Kimi: "Usa keys kimi-...
   en kimi.com/code. Si te da timeout, prueba Moonshot o DeepSeek."
6. **Botones para cambiar a otro proveedor con 1 click**. Muestra los
   3 mas fiables (deepseek, minimax, nvidia) excepto el actual.
   Al pulsar uno:
   - Cambia `APP.config.iaProveedor`
   - Persiste en localStorage
   - Actualiza el select de Ajustes > IA
   - Muestra un toast verde confirmando
   - Cierra el dialogo
7. **Respuesta cruda del modelo** en `<details>` colapsable (max 1500
   chars) si la IA devolvio algo parseable.

### Cambios en los call-sites

- `aiPatronesUI` y `aiAnalizarLoteUI` ahora ambos usan
  `mostrarDialogoErrorIA(r, '<contexto>')`. Antes uno mostraba dialog
  y el otro solo un `adviceErr` (toast).

## Ejemplo del nuevo dialogo

```
┌─ Error al detectar patrones ───────────────────────────────┐
│ Proveedor: Kimi for Coding (kimi.com)                       │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ https://api.kimi.ai/coding/v1/chat/completions        │ │
│ └────────────────────────────────────────────────────────┘ │
│ Detalle: No se pudo contactar Kimi for Coding (kimi.com)    │
│ (timeout) [transporte=GM]. Revisa el endpoint.              │
│                                                            │
│ ┃ Sugerencia: Timeout o fallo de red. Verifica tu conexion, │
│ ┃ sube "Timeout" en Ajustes > IA o prueba con otro         │
│ ┃ proveedor.                                               │
│                                                            │
│ Sobre este proveedor: Kimi for Coding usa el endpoint       │
│ /coding/v1 con keys kimi-... Si te da timeout, prueba con   │
│ Moonshot o DeepSeek que suelen ser mas estables.            │
│                                                            │
│ Probar con: [DeepSeek] [MiniMax] [NVIDIA NIM]               │
│                                                            │
│ ▼ Respuesta cruda del modelo                               │
│                                                            │
│                                       [Cerrar]             │
└────────────────────────────────────────────────────────────┘
```

Pulsar **DeepSeek** cambia el proveedor al instante: la proxima vez
que pulses "Detectar patrones" usara `api.deepseek.com` en lugar de
`api.kimi.ai/coding/v1`.

## Compatibilidad

- Cero cambios al flujo de reglas automaticas, caravanas, etc.
- Cero cambios al formato del backup/configuracion.
- Si tu IA funciona bien, no notas nada: el dialogo rico solo aparece
  cuando hay error.
- Los cambios de proveedor persisten en localStorage (como antes).
