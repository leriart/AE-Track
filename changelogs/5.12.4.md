# 5.12.4

Arreglo del **400 de Kimi for Coding**: el modelo solo acepta
`temperature: 1` y Rondo mandaba `0.2`. Ahora `temperature` y `max_tokens`
son **opcionales** (vacios = se omiten y el modelo usa su default).

## El problema

Con el endpoint ya correcto (`/coding/v1`), la autenticacion pasaba y el
modelo respondia:

```
400 invalid temperature: only 1 is allowed for this model
```

El cuerpo de la peticion llevaba `temperature: 0.2` fijo. Varios modelos
recientes (Kimi for Coding entre ellos) rechazan cualquier temperatura que
no sea la suya y devuelven 400.

## Cambios

- **`temperature` deja de ir fija.** Si no defines nada, se **omite** y el
  modelo usa su valor por defecto. Si quieres fijarla, hay un campo
  **Temperatura** en *Ajustes &rsaquo; IA* (0-2).
- **`max_tokens` tambien es opcional.** Si no lo defines, se omite (algunos
  modelos exigen `max_completion_tokens` o rechazan valores bajos). Campo
  **Max tokens** en Ajustes (64-4000).
- Nuevos ajustes `iaTemperature` e `iaMaxTokens`, por defecto vacios.
- **Pista 400**: *"El modelo rechazo un parametro (revisa Temperatura/Max
  tokens o el modelo elegido)"*.
- Ayuda actualizada en la pestana IA.

## Nota

Con esto, la configuracion recomendada para **Kimi for Coding** es dejar
*Temperatura* y *Max tokens* **vacios**. El resto de proveedores
(DeepSeek, NVIDIA, Moonshot, MiniMax) funcionan igual.
