# 5.12.7

Arreglo definitivo de la voz. El error
*"Failed to load because no supported source was found"* significaba que el
`<audio>` **no podia cargar el MP3** de StreamElements: la **CSP de la
pagina** bloquea `media-src`/`connect-src` externos. Ahora el audio se
**descarga por `GM_xmlhttpRequest`** (que no pasa por la CSP) y se reproduce
por **Web Audio** o, si no, desde un blob local.

## El problema

Al reproducir el TTS online con `new Audio(url)`:

```
play: Failed to load because no supported source was found.
```

No era la URL ni CORS (StreamElements manda `Access-Control-Allow-Origin: *`).
Es la **Content-Security-Policy** de AE-Track, que impide que la pagina cargue
medios de dominios externos. Un elemento `<audio>` del DOM queda sujeto a esa
politica; una peticion del gestor de userscripts, no.

## La solucion

1. **Descarga por GM**: `_ttsBytesViaGM(url)` trae el MP3 como `ArrayBuffer`
   con `GM_xmlhttpRequest` (salta CORS **y** CSP).
2. **Reproduce por Web Audio**: `decodeAudioData` + `AudioBufferSourceNode`.
   El Web Audio **no esta sujeto a `media-src`**: una vez tienes los bytes,
   suena seguro.
3. **Fallback a `<audio>` con blob**: si el navegador no puede decodificar,
   se crea un `blob:` local (mismo origen) y se reproduce con `<audio>`.
4. **Fallback final a URL directa** si no hay GM disponible.
5. **Google Translate TTS** (trozos) usa el mismo camino (bytes -> Web Audio).

## Cadena de fallbacks de la voz (de mas a menos preferido)

| Motor | Camino |
| --- | --- |
| Navegador | `speechSynthesis` (si arranca) -> StreamElements |
| Online | StreamElements via GM -> Web Audio -> blob -> Google |
| Google | Google via GM -> Web Audio -> blob |

Con esto, aunque la maquina no tenga TTS del sistema **y** la pagina tenga
CSP estricta, el aviso se oye.
