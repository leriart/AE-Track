# 5.12.1

Arreglo del **401 de Kimi** en la IA de razonamiento, endurecimiento de la
integracion con proveedores (Kimi.ai y Moonshot separados, MiniMax,
endpoint configurable) e **indicador/toggle de IA en la cabecera**.

## Indicador de IA en la cabecera

Junto al boton del **tema** aparece ahora un boton con el icono de robot que
indica de un vistazo el estado de la IA y sirve para activarla o
desactivarla:

| Estado | Aspecto | Al pulsar |
| --- | --- | --- |
| API key configurada + IA activa | robot en verde + **check** | desactiva la IA |
| API key configurada + IA apagada | robot en ambar + **punto** | activa la IA |
| Sin API key | (oculto) | abre *Ajustes &rsaquo; IA* con aviso |

- El toggle controla si la IA se usa para el **analisis de avisos** (el
  boton `IA` de cada tarjeta de Avisos y el propio indicador).
- Si no hay API key, el boton no se muestra; el estado no ocupa cabecera
  hasta que configuras un proveedor.
- El cambio se guarda al instante en `localStorage` y repinta la pestana
  de Avisos para que los botones de analisis aparezcan/desaparezcan.
- El tooltip detalla el proveedor activo y que hace el clic.

## Por que daba 401 con "Kimi"

Kimi tiene **dos productos con endpoints distintos** y las keys no son
intercambiables:

| Producto | Consola | Endpoint API | Keys |
| --- | --- | --- | --- |
| **Kimi.ai** (API general) | kimi.com / kimi.ai | `https://api.kimi.ai/v1/chat/completions` | `kimi-...` |
| **Moonshot** | platform.moonshot.ai | `https://api.moonshot.ai/v1/chat/completions` | `sk-...` |
| **Kimi Code** (suscripcion) | kimi.com/code | `https://api.kimi.ai/coding/v1` | `kimi-...` (plan Code) |

La 5.12.0 mandaba **todas** las keys de Kimi a `api.moonshot.ai`, asi que
una key de `kimi.ai` devolvia `401 Invalid Authentication`. Ahora hay dos
proveedores separados y, ademas, un campo **Endpoint** para pegar la URL
exacta que toque.

## Cambios

- **Nuevo proveedor `Kimi.ai (API general)`**: `api.kimi.ai/v1/chat/completions`,
  modelo por defecto `kimi-k2.5`, pensado para keys `kimi-...`.
- **`Moonshot` se mantiene** como proveedor propio:
  `api.moonshot.ai/v1/chat/completions`, modelo `kimi-k2.6`, keys `sk-...`.
- **Nuevo proveedor `MiniMax`**: `api.minimax.io/v1/chat/completions`,
  modelo `MiniMax-M3`, keys de `platform.minimax.io`.
- **Nuevo proveedor `Personalizado`**: endpoint y modelo vacios; el user
  los rellena. Sirve para cualquier API compatible con OpenAI Chat
  Completions (OpenRouter, Groq, Together, un proxy propio, etc.).
- **Campo `Endpoint (opcional)`** en *Ajustes &rsaquo; IA*: si esta
  relleno, sobreescribe el del proveedor. Util para cambiar de region
  (`api.moonshot.cn` vs `api.moonshot.ai`) o de producto
  (`api.kimi.ai/v1` vs `api.kimi.ai/coding/v1`).
- **Aviso contextual** bajo el selector de proveedor: indica que formato
  de key se espera y cual es el endpoint por defecto.
- **Mensaje de error 401/403 mucho mas util**: en vez del volcado crudo
  del proveedor, explica que la key probablemente sea de otro producto y
  sugiere cambiar de proveedor o ajustar el endpoint.
- La estructura de proveedores ahora declara `headerAuth` y `prefijo`
  (preparado para proveedores que no usen `Authorization: Bearer`, como
  algunos proxys con header propio).

## Notas tecnicas

- `APP.config.iaEndpoint` nuevo (default `''`): se guarda en `localStorage`
  y se trunca a 300 chars.
- `iaLlamarProveedor` resuelve el endpoint con
  `cfg.iaEndpoint || prov.endpoint` y falla con un mensaje claro si falta.
- El modelo tambien es truncado a 120 chars.
- La API key sigue enmascarada en la UI y solo sale al endpoint.
