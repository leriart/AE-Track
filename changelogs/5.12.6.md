# 5.12.6

Arreglo de la **voz que no sonaba**. Causa: en Linux (y en algunos equipos
sin `speech-dispatcher`) la Web Speech API existe pero **no reproduce nada**,
y el script se quedaba en silencio. Ahora hay **fallback automatico a
StreamElements** y el boton de prueba dice que paso.

## El problema

El motor por defecto era **Navegador** (Web Speech API). En Windows/macOS
suele sonar, pero en **Linux** `speechSynthesis` puede existir sin ninguna
voz real: `speak()` no lanza error, simplemente no suena. Como el codigo
tragaba los errores, el usuario no veia nada.

## Cambios

- **Fallback automatico Web -> Online.** Al usar el motor *Navegador*:
  - Si no hay Web Speech API o no hay voces instaladas, se usa
    **StreamElements** directamente.
  - Si hay voces, se lanza y un **watchdog** comprueba a los 1 s si
    arranco; si no (`onstart` no disparo y `speechSynthesis` no esta
    hablando), reproduce por **StreamElements** para que el aviso se oiga
    igual.
- **Boton "Probar voz" con feedback.** Debajo aparece el resultado:
  *"Reproduciendo con web..."*, *"Sin TTS del sistema: reproducido con
  Online"*, *"No se pudo reproducir: ..."*. Ya no se queda en silencio sin
  explicacion.
- **El boton de prueba suena aunque "Voz" este desactivada**, para poder
  comprobar la voz antes de activarla.
- **Voces online validadas**: si la voz guardada no es una de las seis en
  espanol (config antigua), se usa `Mia`.
- **Constructores robustos** (`pageCtor`): `Audio` y
  `SpeechSynthesisUtterance` se resuelven prefiriendo el realm de la pagina
  y cayendo al global, para sobrevivir al sandbox en cualquier gestor.

## Como probar

1. *Ajustes > Avisos*: **Voz** activada.
2. Motor **Navegador** (con fallback) o **Online · StreamElements**.
3. Pulsa **Probar voz**. Si sale *"reproducido con Online"*, tu equipo no
   tiene TTS del sistema y Rondo ya usa el online solo.
