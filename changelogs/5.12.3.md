# 5.12.3

Arreglo del **404 de Kimi.ai**: el endpoint correcto vive bajo **`/coding/v1`**,
no bajo `/v1`. Se verifica con sondeo real y se añaden pistas para 404 y 429.

## El problema

Con el fix de CORS ya salia la peticion, pero `api.kimi.ai` respondia **404 de
nginx**. Sondeo de las rutas reales:

| Endpoint | Resultado |
| --- | --- |
| `https://api.kimi.ai/v1/chat/completions` | **404** (la ruta no existe) |
| `https://api.kimi.ai/coding/v1/chat/completions` | **401** (ruta valida, falta auth) |
| `https://api.moonshot.ai/v1/chat/completions` | 401 (ruta valida, otro producto) |

Kimi.ai solo expone la API de **Kimi Code** bajo `/coding/v1`. La 5.12.2
apuntaba a `/v1`, de ahi el 404.

## Cambios

- El proveedor `kimi` pasa a llamarse **Kimi for Coding (kimi.com)** y su
  endpoint es `https://api.kimi.ai/coding/v1/chat/completions`.
- Modelo por defecto: **`kimi-for-coding`** (K2.8 Preview, el recomendado por
  Kimi). Otros IDs validos: `k3`, `k3-256k`, `kimi-for-coding-highspeed`
  (se pueden poner en el campo *Modelo*).
- Se aclara en el selector y en la ayuda que las keys `kimi-...` son de
  kimi.com/code y usan `/coding/v1`, mientras que las `sk-...` son de
  platform.moonshot.ai y usan `/v1`.
- China: si tu cuenta es de `api.kimi.com`, cambia el host en *Endpoint* a
  `https://api.kimi.com/coding/v1/chat/completions`.

## Mensajes de error mas utiles

- **404**: *"La RUTA del endpoint no existe"* + la nota del proveedor y la URL
  actual, para corregirla en *Endpoint*.
- **429**: *"Limite de uso alcanzado (rate limit)"*.
- **401/403**: recuerda que la key puede ser de otro producto.
