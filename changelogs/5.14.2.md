# 5.14.2

Dos mejoras pequenas pero muy pedidas:

1. **Chip de version al lado del titulo "Rondo"** (antes estaba al
   final de la cabecera, junto al resto de iconos). Ahora se ve
   claramente la version instalada y su estado (al dia / update /
   comprobando / sin comprobar / build ahead) sin tener que buscar.

2. **"Detectar patrones" mas robusto**: el boton fallaba con muchos
   proveedores por dos motivos combinados (prompt muy largo + muestra
   grande -> context length exceeded; modelo devolvia texto en vez de
   JSON -> parse fallido). Ahora el prompt es ~50% mas pequeno, la
   muestra maxima bajo de 200 a 80 alertas, y se anade un fallback
   regex para extraer sugerencias de respuestas en texto libre.

## Cambios

### UI: chip de version al lado del titulo

**Antes**: `[estado-barra] [Rondo] [chip-version] [update] [theme] ...`
El chip estaba pegado a los iconos, visualmente confundido con ellos.

**Ahora**: `[estado-barra] [Rondo v5.14.2] [update] [theme] ...`
El chip vive **dentro del `<h3>`** del titulo, como un badge inline.
Estilo mas discreto (18px de alto, 10.5px de fuente) para no robar
atencion al titulo. Click sigue forzando comprobacion; doble click
abre Ajustes > Avanzado.

Comportamiento sin cambios:
- Verde: al dia
- Rojo pulsante: update disponible (muestra `v5.14.1 -> 5.14.2`)
- Azul: comprobando
- Ambar: unknown / error
- Gris: build local ahead de la remota

### Detectar patrones: fixes

#### Prompt recortado

`IA_SYSTEM_PATRONES` bajo de ~1500 tokens a ~600 (60% menos). Lo que
mas ocupaba era la lista de parametros con descripcion larga de
default y rango. Ahora solo van los **nombres exactos** de los
parametros; los valores actuales van en el JSON de contexto.

#### Muestra limitada a 80 alertas

Antes el limite era `max(50, iaBatchMax*4)` cap 200. Ahora es
`max(15, iaBatchMax*2)` cap 80. Con DeepSeek-chat (8K context) o
cualquier modelo con ventana pequena esto evita la mayoria de los
errores 400 "context length exceeded".

El detalle de cada alerta se trunca a 80 chars (antes 160) para
ahorrar aun mas tokens.

#### Fallback regex

Nueva funcion `extraerPatronesDeTexto(texto)` que busca por regex:

- `"parametro":"X"` + `"valor_sugerido":N` en el mismo bloque ->
  sugerencia
- `"descripcion":"texto largo (>=20 chars)"` -> patron

Si la IA devolvio prosa o JSON malformado pero con estructura
reconocible, se recupera en vez de mostrar error. El dialogo
resultante marca `recuperado de texto` en el titulo para que el
operador sepa que la respuesta no fue 100% limpia.

#### Errores mostrados en dialog (no toast)

Antes `aiPatronesUI` mostraba `adviceErr('Patrones IA', r.error)`:
un toast rojo que se autosecaba en 12 segundos. Si el operador
estaba lejos del teclado, se perdia el mensaje.

Ahora cualquier error abre un **dialogo** con:
- El mensaje completo
- Una sugerencia contextual segun el tipo de error:
  - `context length / too long / max tokens` -> cambiar de modelo o
    bajar "Max avisos por analisis en lote"
  - `401/403` -> la API key no corresponde a este proveedor
  - `429` -> rate limit, esperar o cambiar
  - `400` -> el modelo rechazo parametros
  - `JSON parseable` -> problema del modelo, reintentar
  - `timeout/red` -> problema de red
- Si hay respuesta cruda (`r.raw`), un `<details>` colapsable con la
  salida del modelo (max 1500 chars)

Si algo revienta dentro de `aiPatronesUI` (JSON con campos
inesperados que rompe un `.map`, etc.), un `catch` antes del `finally`
abre otro dialogo con el stack trace. **Antes** el boton se quedaba
en estado "busy" para siempre y el operador solo veia un toast rojo
vacio.

#### Try/catch defensivo en `shouldWatch`

`aiPatrones` calcula `unidadesVigiladas` con `APP.unidades.filter(shouldWatch)`.
Si `shouldWatch` reventara por algun motivo (unidad corrupta en cache,
cambio de API interna), ahora se ignora silenciosamente esa unidad y
se sigue con el resto. Antes podia tumbar toda la llamada.

## Compatibilidad

- Cero cambios al flujo de reglas automaticas, caravanas, etc.
- Cero cambios al formato del backup/configuracion.
- Los dialogos de error nuevos aparecen SOLO si falla algo: el camino
  feliz sigue siendo 1 click -> dialogo de resultados.
