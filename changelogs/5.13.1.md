# 5.13.1

Arreglo de la **deteccion de unidades dentro de una geocerca**. Las
geocercas se cargaban (se veian en la pestana Zonas) pero Rondo nunca decia
que una unidad estaba dentro.

## El problema

El campo `zl` que devuelve `core/search_items` (flag 4096) **solo trae las
propiedades de la geocerca y su bounding box** (`b`: `min_x`, `min_y`,
`max_x`, `max_y`, `cen_x`, `cen_y`). **No incluye los puntos del poligono
(`p`) ni el centro como objeto (`c`)**. La geometria real se obtiene aparte
con `resource/get_zone_data`.

Como `inZone()` solo sabia leer `p` (poligono) y `c` (circulo), para las
zonas cargadas desde `zl`:

- Circulos: no habia `c` -> no se detectaba nada.
- Poligonos: no habia `p` -> no se detectaba nada.
- El unico resto era el bounding box, y en muchos casos el `b` no llegaba
  como se esperaba -> **siempre "fuera"**.

## La solucion

1. **Enriquecer la geometria**: tras leer las zonas del `zl`, Rondo pide
   `resource/get_zone_data` (`flags: 0x1F` = area + perimetro + centro +
   todos los puntos + basicos) por recurso y fusiona `p`, `b`, `t` y `w` en
   cada zona. Si el metodo no existe (Wialon antiguo), se sigue con el
   bounding box como aproximacion.
2. **`inZone()` reescrito** para cubrir todos los formatos reales:
   - **Circulo (t=3)**: centro en `c` **o** en `b.cen_x`/`b.cen_y`, radio en
     `w` (o `r`). Esto hace que los circulos funcionen incluso sin
     `get_zone_data`, porque el `zl` ya trae el centro y el radio.
   - **Poligono (t=2)**: ray-casting sobre `p`, aceptando `p` como array o
     como **string JSON**.
   - **Linea (t=1)**: dentro si esta a `<= w` del trazado (distancia
     punto-segmento).
   - **Sin geometria fina**: cae al bounding box (`b`).
   - Coordenadas normalizadas a numero y descarte rapido por bbox.
3. **`zl` como string**: `_extraerZonasDe` ahora hace `JSON.parse` si el
   campo viene serializado (algunas versiones de Wialon lo devuelven asi).
4. **Contexto de IA**: la geocerca actual de una unidad ahora usa `inZone`
   en vez de un campo inventado.
5. Helper `_geoDistM` (equirectangular local, metros) **autosuficiente**,
   para que `inZone` no dependa de funciones definidas mas abajo.

## Como comprobar

- Pestana **Zonas**: cada tarjeta debe mostrar las unidades dentro.
- KPI **En zonas** del Dashboard debe contar geocercas ocupadas.
- La lista de Unidades muestra la geocerca actual en cada tarjeta.
- La regla **Geocercas** de avisos empieza a disparar.

Si un poligono no trae `p` y `get_zone_data` falla, se usa el bbox (puede
dar algun falso positivo en las esquinas, pero ya no queda todo "fuera").
