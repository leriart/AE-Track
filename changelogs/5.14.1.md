# 5.14.1

Sistema de actualizacion **rehecho** para acabar con el bug que hacia
que Rondo creyera estar desactualizado aunque tuviera la version mas
reciente, y para que el check sea robusto frente a CORS/CSP/fallos de red.

## Problemas que se arreglaron

### 1. La constante `VER` quedaba desincronizada del `@version`

Cada vez que se bumpeaba la cabecera `@version` se actualizaba el
metadata pero el literal `const VER = '5.13.1'` se quedaba atras.
Resultado: la UI siempre decia "tienes 5.13.1, hay update a 5.14.0"
aunque el usuario tuviera 5.14.0 instalada.

**Solucion**: ademas de actualizar el literal a `5.14.1`, el script
hace un **self-check al arrancar**: lee el `@version` del propio archivo
(via `document.currentScript.src` + `GM_xmlhttpRequest`) y avisa si
detecta deriva entre el literal y el header.

### 2. `fetch()` directo a `raw.githubusercontent.com` -> CORS

`raw.githubusercontent.com` NO envia `Access-Control-Allow-Origin`, asi
que el `fetch()` desde el realm de la pagina fallaba en cuanto la
plataforma tenia su propio CSP o el navegador aplicaba el sandbox del
userscript. El script caia silenciosamente al estado `error` y volvia
a `idle` al reintentar.

**Solucion**: `fetchVersionRemota()` ahora usa `httpRequest()`, que
cae a `GM_xmlhttpRequest` (que el sandbox del userscript SI permite
para URLs en `@connect`).

### 3. Cuando fallaba el check, el script mentia

Antes, si el check fallaba, Rondo quedaba en estado `error`/`idle` y
el usuario no sabia si estaba al dia o no. Si el icono de toolbar no
estaba visible, no habia forma de saber.

**Solucion**: estado explicito `unknown` (no `error` generico), chip
de version **siempre visible** en la cabecera del panel con color
segun estado:
- verde: `current` (al dia)
- rojo pulsante: `available` (hay update)
- ambar: `unknown` / `error` (no se pudo comprobar)
- azul: `checking` (en curso)
- gris: `ahead` (build local ahead de la remota)

## Mejoras adicionales

### Multi-source version check (3 fuentes)

El check ahora prueba hasta 3 fuentes independientes, en orden, hasta
que una responda:

1. **Canal main**: `raw.githubusercontent.com/leriart/AE-Track/main/rondo.user.js`
2. **Canal dev**: `raw.githubusercontent.com/leriart/AE-Track/dev/rondo.user.js`
   (solo si el build local va por delante de main)
3. **GitHub API**: `api.github.com/repos/leriart/AE-Track/contents/changelogs`
   (lista el directorio de changelogs y toma el archivo `.md` con la
   version mas alta)

### `@connect` explicitos

Se anadieron `@connect raw.githubusercontent.com` y `@connect api.github.com`
para claridad (ya estaba el wildcard `*`, pero los explicitos son mejores
para auditoria y para los gestores que aplican politicas estrictas).

### Persistencia del ultimo check

`lastCheck` y `state` (solo `current`/`unknown`) se guardan en
`localStorage` bajo `rondo.api.update`, asi el chip de version muestra
el timestamp correcto incluso despues de recargar.

### Re-check al recuperar foco

Ademas del intervalo fijo de **6h** (antes 30min -> demasiado ruido),
el script re-comprueba al volver a la pestana (`focus` + `visibilitychange`),
con un throttle de 1 minuto. Esto cubre el caso de "estuve offline
un rato, ahora tengo red, comprobar de nuevo".

### Click del chip de version

- **Click simple**: si hay update, abre el dialogo de aplicacion. Si
  no, fuerza una re-comprobacion.
- **Doble click**: abre **Ajustes > Avanzado** (donde esta el boton
  "Buscar actualizaciones" y el detalle completo).

### `cmpVersion` / `parseVersionHeader` mas robustos

- `parseVersionHeader` ahora acepta cualquier input (no revienta con
  null/undefined/numero) y devuelve `null` si no encuentra patron
  valido.
- `cmpVersion` normaliza a lowercase y filtra caracteres no numericos,
  para que pre-release tags como `5.14.1-beta` se comparen bien.

## Como se ve ahora

| Antes | Ahora |
|---|---|
| `VER = '5.13.1'` constante olvidada | `VER = '5.14.1'` + self-check al arranque |
| `fetch()` -> CORS -> `error` | `httpRequest()` -> GM_xmlhttpRequest |
| Sin feedback visual cuando fallaba | Chip siempre visible con color |
| 30 min de poll | 6h + re-check al foco |
| Una sola fuente (raw) | 3 fuentes (raw, dev, GitHub API) |
| lastCheck perdido al recargar | Persistido en localStorage |
| Click solo en toolbar | Click en chip de cabecera |

## Compatibilidad

- Cero cambios al flujo de reglas automaticas, IA, caravanas, etc.
- Cero cambios al formato del backup/configuracion.
- Si tienes una version vieja de Rondo instalada, **re-instala** desde
  `https://raw.githubusercontent.com/leriart/AE-Track/main/rondo.user.js`
  para aplicar esta version (la auto-actualizacion solo funciona
  dentro de la misma sesion, no entre versiones de un script que
  estaba broken).
