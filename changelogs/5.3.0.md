# 5.3.0

Capa optativa de **zonas de riesgo** para flotas vehiculares. Rondo ahora
puede consultar un CSV o JSON con zonas de alto riesgo y disparar una
alerta critica cuando una unidad transiciona de con-senal a sin-senal
estando dentro de uno de los buffers configurados.

La idea de fondo: si una unidad deja de reportar y su ultima posicion
valida cae dentro de una zona con alta incidencia de delitos contra
flotas (robo de vehiculo, robo a transporte de carga, asalto, etc.), la
alerta vale mas que un "sin-senal" generico. Es un evento que amerita
contactar al conductor o a la autoridad.

## Cambios principales

- **Nueva pestana "Riesgo"** (septima pestana del panel). Muestra:
  - Estado del dataset: cargando / cargado / error / sin configurar.
  - URL actual y botones **Recargar**, **Importar archivo** y **Limpiar**.
  - Parametros: formato (auto, CSV, JSON), score minimo, multiplicador
    de radio.
  - Lista de zonas cargadas (top 200 ordenadas por score).
- **Nueva regla `riesgoSinSenal`**: alerta **critica** cuando una unidad
  transiciona de online a offline y su ultima posicion valida cae
  dentro del buffer de una zona cargada. El mensaje en pantalla es
  `PERDIO SENAL EN ZONA DE RIESGO \u00b7 <unidad>` y el TTS dice
  *"Atencion critica. La unidad <eco> perdio senal en zona de riesgo"*.
- **Soporte de multiples fuentes** sin tocar el repo:
  - URL remota (CSV o JSON) que el usuario pega en Ajustes > Riesgo.
  - Archivo local (CSV/JSON/TSV/TXT) desde el boton **Importar archivo**.
  - El dataset vive solo en memoria; **nada se persiste** en
    localStorage, `data/` o el repositorio.
- **Sin carga por defecto**: `riesgoUrl` arranca vacio. Rondo no intenta
  cargar nada hasta que el usuario configure una URL o importe un
  archivo.
- **Formatos aceptados**:
  - **JSON**: `{ items: [...] }`, `{ features: [...] }` (GeoJSON
    FeatureCollection) o un array directo.
  - **CSV** / **TSV**: una fila por zona. Rondo autodetecta las
    columnas por nombre (`lat`/`latitud`, `lon`/`lng`/`long`,
    `score`/`severidad`/`riesgo`, `radio_m`/`radio`/`buffer`,
    `estado`, `municipio`, `delito`, `conteo`). Las filas se agrupan por
    coordenadas y se suman los conteos por tipo de delito.
- **Sin datos en el repo**: a diferencia del intento previo, esta
  version **no incluye ningun dataset**. El usuario decide donde hospeda
  su informacion y la ruta es enteramente configurable desde Ajustes.

## Esquema del dataset recomendado

El JSON sigue este patron (compatible con versiones previas):

```json
{
  "version": 1,
  "fuente": "<nombre o url del proveedor>",
  "licencia": "<CC-BY 4.0 u otra>",
  "generado": "YYYY-MM-DD",
  "items": [
    {
      "id": "mx-09001-cuauhtemoc",
      "estado": "CDMX",
      "municipio": "Cuauht\u00e9moc",
      "centro": [19.4326, -99.1332],
      "radio_m": 1500,
      "score": 78,
      "fuente": "sesnsp",
      "delitos": { "robo_vehiculo": 5, "asalto": 12, "homicidio": 1 },
      "nota": "opcional"
    }
  ]
}
```

Para CSV el header equivalente seria:

```
id,estado,municipio,lat,lon,radio_m,score,delito,conteo
mx-09001-cuauhtemoc,CDMX,Cuauhtemoc,19.4326,-99.1332,1500,78,robo_vehiculo,5
mx-09001-cuauhtemoc,CDMX,Cuauhtemoc,19.4326,-99.1332,1500,78,asalto,12
```

Alternativas equivalentes de nombre de columna (todas detectadas):

- Latitud: `lat`, `latitud`, `latitude`, `y`.
- Longitud: `lon`, `lng`, `long`, `longitude`, `longitud`, `x`.
- Score: `score`, `severidad`, `riesgo`, `incidencia`, `peligrosidad`.
- Radio: `radio_m`, `radio`, `buffer`, `distancia`, `distancia_m`.
- Estado / municipio: `estado`, `entidad`; `municipio`, `ciudad`,
  `alcaldia`.
- Delito / conteo: `delito`/`tipo`/`categoria` + `conteo`/`count`/
  `casos`/`incidentes`/`valor`.

## Detalles tecnicos

- Funciones puras aisladas entre `/* ====================== RIESGO ====================== */`:
  - `_splitCSVLine`, `_parseCSV`, `_autoSep`, `_findCol`: parser CSV
    minimo compatible con datos abiertos mexicanos.
  - `_normItem`, `_itemsFromJSON`, `_itemsFromCSV`: normalizacion que
    valida cada item (lat en \xb1 90, lon en \xb1 180, radio > 0).
  - `radioRiesgoEfectivo`, `puntoEnZonaDeRiesgo`: busqueda espacial
    O(n) por haversine. Para datasets mayores a ~5 000 zonas se
    recomienda una grilla por buckets; esta version no la incluye
    porque el caso de uso tipico son unos cuantos cientos de zonas.
- `cargarRiesgo(url)`: usa `fetch()` con `cache: 'no-store'` y CORS
  abierto. El guard `APP._riesgoFetched` evita fetches duplicados si la
  misma URL se pide varias veces seguidas.
- `reglaRiesgoSinSenal(st, prev, R, info, etq)`: misma firma que el
  resto del motor de reglas. Solo dispara en la transicion online
  \u2192 offline (controlada por `prev.estado !== 'offline' && st.estado
  === 'offline'`), reutiliza la ultima posicion valida (`st.lat` o
  `prev.lat`) y resetea `R.riesgoSinSenalAlerta` cuando la unidad
  vuelve a reportar.
- Estado nuevo en `APP`: `riesgo`, `riesgoTs`, `riesgoErr`,
  `riesgoEstado`, `_riesgoFetched`. **Nada** se escribe en
  `localStorage` ni en `sessionStorage`.
- Constantes nuevas: `LS.riesgo`, `SS.riesgo`, `MAT.riesgo` (`E160`,
  "report" de Material).
- Defaults nuevos en `DEFAULTS`: `riesgoUrl: ''`,
  `riesgoFormato: 'auto'`, `riesgoMinScore: 1`, `riesgoRadioMul: 1`.
- Regla nueva en `DEFAULTS.reglas`: `riesgoSinSenal: true` (activada
  por defecto pero neutralizada por la falta de dataset).

## Compatibilidad

- Cuando `APP.riesgo` esta vacio (estado inicial), `reglaRiesgoSinSenal`
  retorna inmediatamente sin alertar. La regla es **optativa** y
  silenciosa: si no hay dataset, no hay ruido.
- Si la URL falla (HTTP 4xx/5xx o CORS), Rondo no intenta re-fetch
  automaticamente. El usuario debe pulsar **Recargar** o cambiar de
  URL.
- Los nombres de columna CSV son flexibles pero **el radio es
  obligatorio**: si una fila no tiene radio explicito y no hay columna
  `score`, se descarta con un warning en consola. Asi evitamos zonas
  puntuales sin buffer que dispararian al pasar encima.
- El radio por score se estima dentro de `_itemsFromCSV` cuando el CSV
  no tiene columna `radio_m`: 4.5 km (>=70), 2.2 km (>=50), 1.4 km
  (>=30), 0.5 km (resto). Esto fue inspirado en el dataset original de
  Rondo 5.3 que **no** se incluye en esta version.

## Tests

No se agregan tests automatizados en este release: la logica espacial es
trivialmente equivalente a `haversine` ya probada y los parsers CSV/JSON
son funciones puras sin dependencias del navegador. Se documenta el
contrato en este changelog y se valida manualmente con un CSV de
pruebas.

## Seguridad y privacidad

- **Sin telem**: nada de lo que el usuario configure se envia a un
  servidor propio.
- **Sin cache en disco**: el dataset vive solo en memoria; al recargar
  la pestana o cerrar el navegador se vuelve a pedir a la URL
  configurada.
- **Sin pishing**: la URL es pegada por el usuario a mano. Rondo no
  intenta descubrir endpoints automaticamente ni usa proxies.
- **HTTPS friendly**: si la URL es HTTPS, Rondo la respeta; si es
  HTTP, igual la carga (pero la mayoria de los navegadores warn
  sobre mixed content).
